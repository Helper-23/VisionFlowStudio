1. 软件概述

VisionFlow Studio 是面向工业检测项目的 Windows 桌面软件。它将多工站、多产品型号和多流程组织在同一个加密项目中，并统一管理相机采图、VisionMaster、VisionPro、HALCON、C# 高级脚本及 PLC/工业协议通信。

典型执行链为：触发 → 相机采图 → 视觉流程 → 结果判定 → 通信写入 → 日志与图像显示。流程采用顺序节点模型，每个节点可以启用、禁用、单独运行、从当前节点运行，并配置超时及错误策略。

支持环境：.NET Framework 4.8 x64；VisionMaster 4.4、VisionPro 7.3、HALCON 18.11；Basler、海康机器人/Hikrobot、Dahua 工业相机；Siemens S7Net、Mitsubishi MC ASCII、Modbus TCP/RTU、Omron FINS TCP、Allen-Bradley EtherNet/IP。

2. 快速入门

  1. 通过“文件 → 新建项目”创建项目，进入“项目 → 型号 / 工位 / 相机 / 通信配置”建立实际生产结构。
  2. 在工站下选择型号并新建一个或多个流程。双击项目树中的流程即可切换当前编辑对象。
  3. 使用工具栏“选择节点”添加相机采图、视觉平台、判定、脚本或通信节点，并按生产顺序排列。
  4. 在右侧属性区配置节点参数。数据源、视觉输出和通信通道尽量使用下拉列表选择，避免手工拼写错误。
  5. 先用“单步”验证每个节点，再执行“单次运行”。确认稳定后再启用连续运行或 PLC 通讯触发。
  6. 通过“文件 → 保存项目”设置至少 6 位方案密码。项目以加密 .vfsproj 文件保存。
调试建议：先离线图像验证算法，再连接相机验证曝光与触发，最后连接 PLC。这样可以快速定位问题属于图像、算法还是通信层。

3. 项目、工站、型号与流程

最新项目结构以工站为生产设备实体，以型号为产品配方，二者形成工站-型号关联，每个关联可以拥有多个流程。

对象用途建议命名
项目一台设备或一条产线的完整配置客户_设备_版本
工站独立相机/执行机构/节拍单元Station_01、上料检测
型号产品配方，可在多个工站复用Model_A、产品料号
流程一个可独立运行和显示的检测序列MainFlow、OCR_Check

流程树支持右键“保存、重命名、删除”。删除前应确认 PLC 触发配置、通信写入映射和脚本中没有继续引用该流程。每个流程拥有独立图像画面；生产监控页可同时显示多个工站/型号/流程的结果。

4. 流程编辑与节点执行

流程表格显示顺序、启用状态、名称、类型、平台、状态、耗时和信息。节点运行结果包含 Idle、Ok、Ng、Error、Skipped。

  • 复制/删除：复制当前节点参数或从流程移除。
  • 上移/下移：改变数据产生和消费顺序。通信节点必须位于其数据源节点之后。
  • 启用/禁用：禁用节点运行时显示 Skipped，不参与判定。
  • 错误策略：StopFlow 立即终止；Continue 记录错误后继续。
  • 超时：相机硬触发等待应设置为大于实际触发周期；视觉平台超时应覆盖最坏算法时间。

5. 工业相机管理

打开“工具 → 工业相机管理”时软件会自动搜索设备。选择设备后执行连接，并通过实时预览观察曝光、增益、像素格式和帧率的效果。

参数说明注意事项
曝光时间单位通常为微秒应小于工位节拍，运动目标需防拖影
增益提升亮度同时放大噪声优先调整光源和曝光
触发模式Off 连续/自由采集；On 等待触发硬触发必须同时选择正确 TriggerSource
触发源Software 或 Line0/Line1 等硬件线确认电平、边沿和接线
像素格式Mono8、Bayer、RGB 等算法输入类型必须匹配
UserSet相机内部参数组“应用参数”只修改当前会话；需要掉电保持时再保存到 UserSet
设备无访问权限：先关闭 MVS/MV Viewer、VisionMaster 和其他占用相机的软件；确认没有残留 VisionFlowStudio 进程；刷新设备后重连。管理员权限通常不是根因，GigE 相机还应检查网卡 IP、子网、巨帧和防火墙。

6. VisionMaster、VisionPro 与 HALCON

VisionMaster

节点加载 .sol，选择流程名，并将上游图像写入配置的图像输入。调试窗口可以编辑 Solution/模块参数并保存。通讯下拉输出来自流程公开 Output；新增输出后必须保存 Solution，回到主界面刷新或重新加载节点输出。

VisionPro

节点加载 .vpp CogToolBlock。输入图像写入指定终端，基础类型输出会暴露给判定、脚本和通信节点。调试窗口承载 ToolBlock 编辑控件，保存后下次运行自动使用更新文件。

HALCON

节点执行 .hdvp 外部过程。图形输入、图形输出、控制输入和控制输出名称必须与过程接口一致。接口结构调整后保存并重新加载；复杂调试建议在 HDevelop 中完成，平台内编辑器用于接口、调用参数和快速验证。

8. 工业通信与多地址写入

先在“工具 → 通信配置”创建通道。窗口打开时会测试通道连接，并在窗口底部显示结果。流程中的通信写入节点通过下拉框选择通道和已暴露的视觉输出，可添加 N 条“数据源 → PLC 地址 → 数据类型”映射。

协议地址示例要点
Siemens S7NetDB1.0、DB10.4型号、Rack、Slot 与 PLC 匹配
Mitsubishi MC ASCIID100、M100确认 ASCII 模式和网络号/站号
Modbus TCP/RTU0、100、x=3;100功能码、站号、字节序需一致
Omron FINS TCPD100、CIO100节点号和地址区正确
Allen-Bradley EIPTagName使用 PLC 标签名及匹配数组长度

支持 Bool、Byte、Int16/UInt16、Int32/UInt32、Int64/UInt64、Float、Double、String 及相应数组。字符串和数组要确认 PLC 端缓冲区长度。通信节点中的每条映射独立记录成功或失败信息。

9. 单次、连续、硬触发与 PLC 触发

  • 单次运行：完整执行一次当前流程。
  • 连续运行：循环执行流程。相机为硬触发时，CameraGrabNode 每轮等待下一帧硬触发，然后继续执行后续节点。
  • 通讯触发：轮询指定通道和地址，根据数据类型、触发值和边沿启动流程。建议使用上升沿并在流程结束后由 PLC 或软件复位握手位。
  • 单步：仅运行选中节点；要求所需上游数据已经存在。
  • 从当前运行：从选中节点执行至末尾，适合调试流程后半段。
硬触发等待时间由相机节点超时控制。若生产节拍可能为 10 秒，相机节点超时不应仍为 1 秒；停止按钮会取消等待并释放循环。

10. C# 高级脚本

脚本节点提供接近常规 C# 的完整类编辑方式、语法高亮、诊断、自动完成、参数提示、外部 DLL 引用和 using 管理。脚本必须继承 VisionFlowAdvancedScriptBase，常用入口为 Initialize() 和 Run()。

public override void Run()
{
    var code = Get<string>("VisionMaster 流程.CodeStr");
    SetOutput("Code", code);
    SetOutput("IsOK", !string.IsNullOrWhiteSpace(code));
}

Get<T>("Key") 读取流程数据；GetNodeOutput<T> 和 GetNodeInput<T> 按节点读取；SetOutput 发布脚本输出；CancellationToken 用于响应停止。添加外部 DLL 后还要添加对应 namespace。DLL 位数和目标 Framework 必须兼容当前 x64/.NET Framework 4.8 进程。

11. 图像与结果

每个流程对应一个独立图像文档。多画面监控适合生产同时查看多个工站；单画面查看用于调试；双击卡片或点击“弹出选中画面”可打开独立窗口。

  • 滚轮：以鼠标位置缩放。
  • 按住左键拖动：平移图像。
  • 双击/“适应”：自动适配窗口。
  • “1:1”：按原始像素显示。
  • 鼠标移动：显示 X、Y 和灰度/颜色值。

12. 系统设置

  • 开机软件自启动：写入当前用户启动项，不需要管理员权限。
  • 启动时最大化：主窗口显示后最大化。
  • 自动加载指定方案：保存加密项目路径和受 Windows 当前用户保护的密码。
  • 界面语言：简体中文和 English，可即时切换并在下次启动保持。
  • 自动保存：手动开启，设置 1～1440 分钟。只有已经保存且密码可用的加密项目会被自动保存，流程运行中自动顺延。

13. 加密、保存和备份

.vfsproj 是当前项目的唯一正式持久化格式，包含项目结构、工站、型号、多个流程、节点参数、相机与通信配置。文件使用基于密码的认证加密，错误密码或文件被篡改都会拒绝加载。

项目密码无法由软件找回。请在受控的密码管理系统中保存，并对项目文件、SOL/VPP/HDVP、脚本 DLL 和相机 UserSet 做版本化备份。

“保存项目”覆盖当前项目文件；“另存为项目”创建新文件并可设置新密码。流程菜单中的独立流程文件只用于流程交换或调试，不代替完整项目备份。

14. 故障排查

现象检查顺序
软件启动失败确认 x64、.NET 4.8、各视觉 SDK 路径；查看运行日志；暂时取消自动加载项目。
SOL 加载 NullReference确认 VM 版本与引用一致、Solution 可由官方 VM 打开、流程名存在；关闭占用后重新加载。

VisionFlow Studio — English Guide

Overview

VisionFlow Studio is an x64 industrial vision workflow application for multi-station, multi-recipe and multi-flow projects. It integrates industrial cameras, VisionMaster, VisionPro, HALCON, C# advanced scripting and PLC communications in one encrypted project.

Getting Started

  1. Create a project and define recipes, stations, cameras and communication channels.
  2. Create one or more flows for each station/recipe pair.
  3. Add nodes in execution order: acquisition, vision, judgment, communication and logging.
  4. Configure node inputs using drop-down lists whenever available.
  5. Validate nodes with Single Step, then Run Once, Continuous Run or PLC Trigger.
  6. Save the project as an encrypted .vfsproj and retain the password securely.

Camera and Triggering

The camera manager searches devices when opened and provides live preview for exposure and gain tuning. Free-run mode continuously supplies frames. With hardware trigger enabled, each continuous-flow iteration waits for the next triggered frame. Set the camera-node timeout above the longest expected trigger interval.

Vision Platforms

VisionMaster nodes load SOL solutions and expose published flow outputs. VisionPro nodes load VPP ToolBlocks and publish primitive outputs. HALCON nodes execute HDVP external procedures with explicit iconic/control interfaces. Save vendor project changes and refresh output discovery after adding or renaming outputs.

PLC Communications

Create and test channels before using a Communication Write node. Each node supports multiple mappings from a vision output to a PLC address and data type. Supported protocols include Siemens S7Net, Mitsubishi MC ASCII, Modbus TCP/RTU, Omron FINS TCP and Allen-Bradley EIP.

Advanced C# Script

Scripts use a full class derived from VisionFlowAdvancedScriptBase. Use Get<T>, GetNodeOutput<T> and SetOutput. External assemblies must target a compatible .NET Framework and x64 process. Use Ctrl+Space for completion, F6 to compile and F5 to run.

Saving, Security and Settings

Projects are authenticated and encrypted. Passwords configured for automatic loading are protected with the current Windows account. Automatic save is disabled by default, supports a 1–1440 minute interval, and is deferred while a flow is running. Display language can be switched between Simplified Chinese and English immediately.

Troubleshooting

For camera access errors, close vendor viewers and other owners, refresh and reconnect. For missing data, run the source node first and refresh published outputs. For PLC timeouts, verify address, port, CPU/rack/slot or station number and firewall. For script load failures, verify architecture, framework version and dependent DLLs.
